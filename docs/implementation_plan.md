## [Overview]

**Что делаем.** Мини-сайт бренда женских рубашек больших размеров (54–72) с единственным целевым действием — переход в личный диалог с автором бренда. Сайт не продаёт онлайн: он показывает вещи, снимает страхи по посадке и качеству и переводит посетителя в мессенджер, где заказ согласуется вручную.

**Как делаем.** Статическая генерация на Hugo: контент — Markdown и YAML-данные в git, сборка — GitHub Actions, деплой — на хостинг в РФ по SSH. Никакого бэкенда, базы данных, корзины и форм, собирающих персональные данные. Вся динамика (фильтр каталога по размеру, аккордеон FAQ, cookie-баннер) — на ванильном JS.

**Почему так.** Аудитория приходит с телефона из ВКонтакте и хочет сначала поговорить, а не «оформить заказ». Статика даёт максимальную скорость на мобильном, нулевую стоимость поддержки, отсутствие рисков взлома и минимум персональных данных на сайте. Hugo выбран как генератор, который отдаёт готовый HTML без клиентского рендеринга и не требует Node.js в продакшене.

### Границы проекта

**Входит:** дизайн-система, вёрстка 8 страниц, каталог моделей, фильтр по размеру, deep-links в мессенджеры, SEO-разметка, cookie-баннер с предварительным согласием, юридические страницы, CI/CD, документация для владелицы.

**Не входит:** корзина, онлайн-оплата, личный кабинет, регистрация, CMS с админкой, поиск по сайту, мультиязычность, блог, e-mail-рассылки, мобильное приложение, интеграция с 1С/складом.

### Допущения

1. Домен и доступ к DNS есть у владелицы; хостинг в РФ оплачен на год.
2. Фотографии владелицы и рубашек будут сделаны (критический путь — см. этап M3).
3. Диапазон размеров — **54–72**; наличие 50–52 уточняется (см. «Открытые вопросы»).
4. Цены публикуются на сайте и совпадают с ценами в диалоге.
5. Тексты политики и оферты проверяет юрист; план задаёт структуру и обязательные пункты, но не заменяет консультацию.

### Цели и метрики (KPI)

| Метрика | Целевое значение | Как измеряем |
| --- | --- | --- |
| Доля визитов, завершившихся кликом в мессенджер | ≥ 8% | цели Метрики `click_tg`, `click_vk`, `click_wa`, `click_max` |
| Конверсия карточки модели в диалог | ≥ 25% | событие `model_cta` с параметром модели |
| Mobile Performance (PageSpeed) | ≥ 90 | Lighthouse в CI (бюджет: JS ≤ 30 КБ, CSS ≤ 60 КБ) |
| LCP / CLS / INP | ≤ 2,5 с / ≤ 0,1 / ≤ 200 мс | Lighthouse + Метрика |
| Глубина просмотра | ≥ 2,5 страницы | Метрика |
| Доля отказов на главной | ≤ 55% | Метрика |

Заявки в классическом смысле не считаются: их нет. Учёт обращений ведётся вручную в реестре заказов (см. часть 3, п. 3.3).

### Сценарии использования

1. **«Пришла из ВК с телефона».** Видит фото и заголовок → пролистывает преимущества → открывает каталог → жмёт «Написать про эту модель» → попадает в Telegram с готовым текстом обращения.
2. **«Боится промахнуться с размером».** Идёт в FAQ и на блок размеров, сверяет мерки, при сомнении жмёт «Спросить про размер» → диалог.
3. **«Хочет понять, кому пишет».** Открывает «О бренде», читает историю и блок про колебания веса, затем — «Доставка и возврат» → и только потом пишет.

## Часть 1. Аудит исходного ТЗ (`docs/tz.md`, 196 строк)

### 1.1 Вердикт

Концепция сильная и редкая для ниши: «не магазин, а личный контакт», тон дневника, отказ от корзины. Текст «Обо мне» — готовый смысловой актив: его нельзя переписывать «в маркетинговый язык», только структурировать. Но как **техническое** задание документ неполон: около 60% работ по запуску в нём не описаны, часть требований противоречит друг другу. Готовность к производству: **4/10** (концепция — 9/10, исполнимость — 3/10).

### 1.4 Что в ТЗ уже хорошо (сохраняем без изменений)

- Позиционирование «живая женщина, а не конвейер» и отказ от корзины — редкое и сильное отличие.
- Текст «Обо мне»: живая речь, конкретные детали (7 рубашек на неделю, 118 → 92 кг), его нельзя «причёсывать».
- Понимание болей: давит в груди, тянет в руках, задирается; страх «балахона».
- Палитра и типографика заданы содержательно (тёплый молочный, оливковый, антиква + гротеск).
- Перечень преимуществ сформулирован в терминах выгоды, а не свойств.

## Часть 2. ТЗ для разработки

### 2.1 Принципы реализации

1. **Mobile-first.** 85%+ трафика — телефон. Базовые стили пишутся для 360 px, десктоп — прогрессивное улучшение.
2. **Без JS-фреймворков.** Hugo отдаёт готовый HTML; JS только для фильтра, аккордеона, sticky-панели и cookie-баннера.
3. **Контент отдельно от кода.** Модели, размеры, контакты и FAQ — в `content/` и `data/`, без правок шаблонов.
4. **Ноль ПД на сайте.** Ни одной формы, собирающей имя/телефон/адрес. Только исходящие ссылки в мессенджеры.
5. **Юридические тексты — часть продукта.** `/offer`, `/delivery`, `/privacy` верстаются как обычные страницы и входят в приёмку.

### 2.10 Репозиторий, CI/CD и хостинг

**Ветки.** `main` — продакшн; изменения владелицы — через веб-интерфейс GitHub (кнопка «Edit» в файле) с автоматическим созданием PR; разработчик ревьюит и мержит. Прямые коммиты в `main` запрещены branch protection.

**`build.yml` (на каждый push и PR):**

1. `hugo --minify --gc` (версия Hugo фиксируется в workflow, локальная сборка — той же версии).
2. `yamllint` для `data/*.yaml` и front matter.
3. Проверка, что у каждой модели заполнены `price`, `sizes`, `images[0].alt`.
4. `html-validate` по собранному `public/`.
5. Проверка внутренних ссылок (`lychee`), падение при 404.
6. Lighthouse CI на трёх URL: `/`, `/catalog/`, карточка модели.

**`deploy.yml` (только `main`):**

1. Сборка с `--baseURL https://<домен>/`.
2. `rsync -az --delete public/ user@host:/var/www/mrsmargaritach/releases/<timestamp>/`.
3. Переключение симлинка `current` и `nginx -s reload` (или graceful reload).
4. Хранение 5 последних релизов; откат — переключение симлинка на предыдущий.
5. Секреты: `SSH_HOST`, `SSH_USER`, `SSH_KEY`, `SSH_KNOWN_HOSTS`. Ключ — только для деплоя, без sudo.

**Хостинг.** VPS или shared-хостинг в РФ с SSH и nginx. Требования: HTTPS (Let's Encrypt, автопродление), gzip/brotli, HTTP/2, лимит статики ≥ 5 ГБ, бэкап конфигов в репозитории (`deploy/nginx.conf`). Аналитика и шрифты — единственные внешние запросы, и Метрика только после согласия.

## Часть 3. Продажи как ИП по законодательству РФ

Сайт — витрина и канал связи. Договор розничной купли-продажи заключается дистанционно в переписке, оплата проходит вне сайта. Это законная модель (ст. 497 ГК РФ, ст. 26.1 Закона «О защите прав потребителей»), но она требует полного набора информации на сайте и корректной фискализации. Ниже — обязательный минимум. **Документ не заменяет консультацию юриста и бухгалтера**: пункты, помеченные «проверить», требуют подтверждения специалистом.

### 3.1 Схема сделки

1. Клиентка пишет в мессенджер (из карточки модели или общего CTA).
2. Маргарита уточняет размер по меркам, наличие, цвет, срок пошива и стоимость доставки.
3. Выставляет счёт или ссылку на оплату из личного кабинета облачной кассы.
4. Клиентка оплачивает — формируется чек, чек уходит на e-mail/телефон покупателя.
5. Заказ отшивается/отправляется СДЭК, трек-номер передаётся в переписке.
6. При получении клиентка проверяет товар; при необходимости — возврат через ПВЗ СДЭК (услуга «Клиентский возврат»).

### 3.5 Оплата

**Рабочие каналы (уточнить у владелицы, что уже подключено):**

1. **Ссылка на оплату из личного кабинета облачной кассы** — СБП или карта; чек формируется автоматически, покупателю уходит на e-mail/телефон. Предпочтительный вариант.
2. **Счёт с QR-кодом СБП** — для крупных сумм; чек всё равно обязателен, ссылка на чек отправляется в переписке.
3. **Наличные при самовывозе** (Екатеринбург, Сахарова 29/4) — только с чеком из кассы, в том числе облачной (чек можно отправить на e-mail).

**Правила:**

- На сайте не публикуются номер карты, реквизиты для перевода и «оплата по договорённости».
- В оферте описано: оплата — акцепт оферты; заказ считается принятым после подтверждения размера и наличия; при невозможности исполнить — возврат в течение 10 дней.
- Комиссия эквайринга (обычно 2,5–3,5%) и стоимость доставки закладываются в цену или выделяются отдельной строкой — но не «сюрпризом» после оплаты.
- Возврат предоплаты — не позднее 10 дней с даты требования (ст. 22, 26.1 ЗоЗПП), тем же способом, с чеком возврата.
- Лимит наличных 100 000 ₽ по одному договору установлен для расчётов между организациями/ИП; с физлицами ограничения нет, но ККТ обязательна.

10. **Ответственность сторон** и обстоятельства непреодолимой силы.
11. **Персональные данные**: ссылка на `/privacy`, состав данных, цели.
12. **Разрешение споров**: претензионный порядок, применимое право, подсудность.
13. **Реквизиты и контакты**, дата публикации и версия оферты.

### 3.13 Структура политики ПД (`/privacy`)

1. Общие положения, оператор (ИП, реквизиты), контакты для обращений.
2. Состав обрабатываемых ПД (cookie, IP, идентификаторы Метрики; данные заказа; фото с согласия).
3. Цели обработки (аналитика сайта, исполнение заказа, доставка, бухгалтерия).
4. Правовые основания (согласие, договор, закон).
5. Cookie и аналитика: какие cookie, зачем, как отказаться.
6. Передача третьим лицам (СДЭК, касса/ОФД), поручения на обработку.
7. Сроки хранения и порядок уничтожения.
8. Права субъекта и порядок отзыва согласия (e-mail, 10 рабочих дней).
9. Меры защиты.
10. Изменения политики, дата редакции.
